### T3. Section 4, the 48-hour grace period replaced by what happens

- Superseded in the second pass by T9 (Hivra Cloud computers) and T10 (Hermes agents). The evidence for the Hermes lane below still holds and backs T10. The statement that no code reacts for Hivra computers was true on the earlier branch and is the gap the lapse enforcement closes (flag F1).

- After: `If a payment fails or you cancel, we mark your Hermes agents (our original chat agents) as suspended straight away, unless you still have another paid plan with us. - Wording added after review: "(our original chat agents)" says which product the suspension sentences cover (the audit says computers run by Hivra are what the site sells now; the suspension applies to the older Hermes lane). "unless you still have another paid plan with us" matches the code: `handlePaymentFailed` and the subscription-updated path suspend only when `findOtherLaneEntitlement` finds no other paid route (Apple, yearly token plan, token tier), and `handlePaymentFailed` does nothing when the failed invoice is not on the subscription row. "Computers run by Hivra" is the phrase the opening paragraph of section 4 already uses.
- Evidence, Hermes agents (rows in `hermes_instances`):
  - `lib/services/stripe-webhook-service.ts`: `handlePaymentFailed` and `handleSubscriptionDeleted` both call `suspendInstancesForBilling`, which sets `status=stopped`, `lifecycle_state=suspended` and "no deletion fuse armed". The old 48-hour delete fuse only runs behind `HERMES_BILLING_LEGACY_HARD_DELETE=true`, a kill switch added after the 22 May 2026 incident.
  - `PAYMENT_GRACE_HOURS = 48` (`lib/subscription/plans.ts`) only decides how long a past-due subscription still counts as entitling (`lib/billing/instance-entitlement.ts`). It is not a deletion timer.

The page therefore states no number.
- Evidence, Hivra computers (rows in `hivra_agents`): no code reacts to a failed payment or a ended subscription. `handlePaymentFailed` and `handleSubscriptionDeleted` act on `hermes_instances`; `dunning-grace-enforce`, `stale-suspended-sweep` and `inactivity-sweep` query `hermes_instances` only; the only Hivra-lane sweeps (`app/api/cron/park-idle-hivra-agents`, `purge-error-hivra-agents`, `recover-stuck-hivra-agents`) do not look at billing. A search of `src` found no lapse path; a mechanism outside this repository (provisioner scripts, host jobs, manual practice) would not show here.
- The sentence about Hivra computers describes today's behaviour and promises nothing either way. A lapsed Hivra computer that keeps running unpaid is probably a billing defect, not a policy; see flag F1.
